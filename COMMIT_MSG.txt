M6 ATTRIBUTE_LOOKUP_V1 2026-09-17: __getattr__, __setattr__, __delattr__ hooks on plain classes

The native object model gained the three attribute hooks without closing them
into the property runtime (which stays as its own MRO slot):

- get_attr: still tries the object field map first; if the class defines
  __getattr__ in its MRO, missing names fall through to piton_object_lookup,
  which calls the hook. Methods declared in the class always win (they are
  resolved before get_attr).
- set_attr: when a class defines __setattr__, writes route through the hook.
  Inside the hook body, self.x = v bypasses the hook (deliberate V1 choice,
  mirrors CPython's super().setattr) and writes raw.
- del_attr: same for __delattr__.

Both backends verify the same behavior through differential tests vs CPython.
Obsolete commit-message files dropped; suite green on Windows (289) and Linux
(209).
