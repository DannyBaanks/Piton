# AutoPiton Results (V0)

All numbers below are measured, not asserted. Each run persists
`meta.json` (environment + config + PITON provenance), `results.jsonl` (one
record per program) and `summary.json` under `autopiton/reports/runs/<run-id>/`.
Reproduce any line with `python3 -m autopiton replay <case-id>`.

## Generated corpus — `run_20261030_163754_generated_seed42` (100 programs, seed 42)

| Classification | Count | % of executed |
|---|---|---|
| EQUIV | 89 | 89.0% |
| DIVERGENT | 11 | 11.0% |
| (all others) | 0 | — |

100/100 executed. **Unique divergence signatures: 2.** All 11 divergences are
output-only (`both completed but observable output differs`), and they collapse
into two genuine defect classes:

### Class 1 — `stdout:bool->int` (7 programs)
PITON prints booleans as `1`/`0`; CPython prints `True`/`False`.

```
v1 = lambda v2: False == -4
print(v1(77 << 0))
CPython: False      PITON: 0
```

### Class 2 — `stdout:float->int` (4 programs)
PITON prints a float value as its raw IEEE-754 bit pattern interpreted as an
int64 — a real numeric-printing defect.

```
class C1:
    def f1(self, v1):
        return v1 / 2
obj = C1()
print(obj.f1(9))
CPython: 4.5        PITON: 4616752568008179712   (= float bits of 4.5 as int64)
```

## Systematic corpus — `run_20261030_170633_systematic` (58 programs)

A second, **non-random** corpus exercises the whole pipeline against an
enumerated grid: **op × operand-kind × surface**, generated by AutoPiton's
`SystematicGrid` rule. Zero programs are hand-written; the rule is the
corpus. This tests whether AutoPiton *replicates* a systematic pass, not just
whether it can sample one.

Grid definition (from `autopiton/generator.py`):

- Arithmetic ops `+ - * / // %` on `int×int (7,3)` and `float×float (7.5,3.5)`
  → 12 cells
- Comparison ops `== != < <= > >=` on `int×int` and `bool×bool` → 12 cells
- Bitwise ops `& | ^ << >>` on `int×int (17,3)` → 5 cells
- **2 surfaces per cell**: `direct` (`print(expr)`) and `lambda` (`_v = lambda:
  expr; print(_v())`)
- Total: **29 × 2 = 58 programs**

| Classification | Count |
|---|---|
| EQUIV | 39 (67.2%) |
| DIVERGENT | 19 (32.8%) |
| **Unique divergence signatures** | **2** |

### Every divergence is on the `lambda` surface

| Kind / surface | Signature | Cells |
|---|---|---|
| `arith_float/lambda` | `stdout:float->int` | 6/6 |
| `arith_int/lambda` | `stdout:float->int` | 1/6 (only `/`, whose result is float) |
| `compare_bool/lambda` | `stdout:bool->int` | 6/6 |
| `compare_int/lambda` | `stdout:bool->int` | 6/6 |
| `arith_int/direct`, `arith_float/direct`, `compare_*/direct`, `bitwise_int` | *(EQUIV)* | 0 |

Two findings this grid produces that the 100-program random corpus could not:

1. **The defect fires only when a value crosses a callable boundary.** Direct
   `print(7.5 + 3.5)` prints `11.0` correctly in PITON; `_v = lambda: 7.5 +
   3.5; print(_v())` prints `4622382067542392832`. Same for bools. This narrows
   the search inside PITON's MIR/lowering to the callable-return path.
2. **Coverage is complete on the axis**: every arithmetic-float cell diverges,
   every comparison cell on the lambda surface diverges, and no direct-surface
   or bitwise cell diverges. A random sample cannot prove that; enumeration can.

An earlier grid pass without the surface axis (`run_20261030_170447_systematic`,
29 direct-only programs) produced 29/29 EQUIV — it is preserved as evidence of
the *falsification* that led to adding the surface dimension.

## Synthesis — `run_20261030_193229_synthesis_seed7` (colorsys, 12 API cases)

Measured on PITON commit `2f24a01e` with a dirty tree (the AutoPiton files
only). `synthesize` writes a module PITON lacks by translating CPython's
source with the project's own ADAPT rule
(`tools.parity_corpus_v4.python_to_piton`), then registers it through the
sandbox overlay: the bundled catalog is extended inside the worker process
only, so `piton/` is never written and each executed case records the
candidate's `overlay_sha256`.

| Pass | EQUIV | INVALID_REFERENCE | DIVERGENT |
|---|---|---|---|
| Baseline (stock compiler) | 0 | 0 | 12 |
| With candidate (sha `eb40f2fa…`) | 1 | 3 | 8 |
| Control: one comparison flipped per public function (sha `1931fb8a…`) | 0 | 3 | 8 (+1 INVALID_ACCEPTED) |

The single EQUIV is `hsv_to_rgb(1, 2, 7)`: baseline DIVERGENT, overlay EQUIV,
`overlay_sha256` equal to the candidate's. In the control run the same case is
DIVERGENT and `hsv_to_rgb([3, 1, 2], 1, False)` becomes INVALID_ACCEPTED — the
pipeline accepts a rule-written body, and the oracle rejects a wrong one on
the same sample. (The first control attempt,
`run_20261030_193417_synthesis_seed7`, flipped a comparison in a function no
case exercised and stayed at 1/12; it is kept as a falsified control design.)

Remaining blockers, attributed per module with the candidate registered:
float arguments crossing call boundaries are reinterpreted as int64 bit
patterns (`colorsys` — a by-hand probe prints `9199052598866975130` for
`add(0.2, 0.5)`) and two overlay builds segfault (exit 139); `nturl2path`
loses the binding of lazy dotted imports (`NameError: name urllib`);
`glob`, `statistics`, `ipaddress`, `uuid`, `configparser` are rejected at MIR;
`stringprep` needs a missing `unicodedata` table; `quopri` needs bytes
parameters; `ntpath` hits ADAPT list concatenation; `csv` raises
MiniBuildError. This is the same boundary the systematic grid found: the
callable boundary, not the module text.

## Limits of these results

- Sample size is 100 seeded programs over a restricted expression sublanguage.
- Synthesis is measured on one module (`colorsys`) and 12 generated API calls;
  INVALID_REFERENCE cases are excluded from the valid denominator, so 1/12 is
  over all generated cases, not over the valid ones.
- Divergences in the V0 corpus are output-formatting/numeric-printing, not
  crashes; the synthesis runs add two segfaults (exit 139) under the overlay,
  recorded in their artifacts and not yet analyzed.
- The PITON tree was dirty; re-measure against a tagged commit before treating
  any defect as canonical in the genealogy.
